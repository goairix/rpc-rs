# Rust RPC 实施计划

**目标**　Go 和 Rust 服务通过同一个 etcd 发现对方，用同一份业务 proto 完成调用。Rust 对外使用 tonic 的标准状态码。

**技术与边界**　Rust 库使用 tonic、prost、Tower 和 Tokio。注册记录兼容 Go 的 JSON，服务器接收生成的强类型服务。测试夹具单独作为 workspace 成员，承载测试 proto、生成代码和进程入口，库消费者只编译库本身。

**规格**　[已确认的设计与错误码验收表](../specs/2026-11-26-rust-rpc-design.md)。以该表为双向测试的预期值。在当前仓库执行，Go 端引用相邻的 `../rpc`。默认 namespace 为 `grpc`，租约 5 秒，etcd 操作超时 2 秒。两端服务名、key 层级与 JSON 字段名相同。

**执行方式**　可在本会话按 executing-plans 顺序实施，也可按 subagent-driven-development 拆分。各任务先运行能复现相应行为缺口的测试，完成后重跑并分别提交可独立验证的变更。

## 实施与验证结果（2026-11-26）

实际代码按职责分为 `crates/naming`（注册、解析及静态与 etcd 后端，原 `crates/registry` 保留兼容导出）、`crates/discovery`、`crates/governance` 和根 crate 的 `src/server.rs`。下文的任务路径为规划时的布局；可运行的入口与配置示例见[仓库 README](../../../README.md)。

- 完整 workspace 通过格式、严格 Clippy 和 33 项测试；本次设置了测试 etcd 与服务端二进制路径，包含所有标记为 ignored 的集成用例。
- `interop/run.sh direct` 和 `interop/run.sh all` 均完成 Go → Rust、Rust → Go 的四种 RPC。通过真实 etcd 完成状态治理、注销、限流和权重热更新，两个调用方向的 60 次请求均从 50/10 变为 10/50。

## 验证重点

| 情形 | 必须观察到的结果 | 对应任务 |
|---|---|---|
| 注册 Put 与首次 watch 之间发生治理更新 | 恢复后沿用同一身份和更新后的状态 | 2 |
| 旧快照事件、旧连接通知晚于新状态到达 | 已下线或已换地址的实例保持最新状态 | 3、4 |
| etcd 仍为 up，但被选中的实例已断开 HTTP/2 | 关闭重试时也能切到另一实例 | 4 |
| 半开探测被取消，或重试等待超过 deadline | 探测名额释放，截止后发出的请求数为零 | 5 |
| 返回响应头后流失败，或客户端提前释放流 | 记录一次正确终态，释放关联资源 | 6 |

## 1. 建立最小跨语言调用

文件：`Cargo.toml`、`src/lib.rs`、`src/metadata.rs`、`interop/proto/echo.proto`、`interop/rust/{Cargo.toml,build.rs,src/main.rs}`、`interop/go/{go.mod,main.go}`、`interop/run.sh`。

- [x] 建立测试服务，提供 Echo、Upload、Download、Chat 四种 RPC。请求携带序号，响应回传序号和实例 ID。Go 模块使用本地 replace，protoc 生成两端桩。生成 descriptor set 供后续反射和方法类型识别共用。
- [x] 用 Go 序列化产生注册样本，测试 `serde_json::from_slice::<ServiceMetadata>` 对 null tags、null properties、缺失权重、未知字段的处理。定义 `ServiceMetadata`、`RegistrationOptions`、`ServiceStatus`，测试两端读取同一记录及默认值。
- [x] 编译两端示例，先做直接地址 smoke 测试。`interop/run.sh direct` 依次启动两种语言的服务，验证对端 Echo 的内容和服务端实例 ID。各进程使用临时端口、就绪通知和退出清理。

## 2. 实现注册生命周期

文件：`src/registry.rs`、`src/registry/etcd.rs`、`tests/registration.rs`。交付 `EtcdRegistry::connect(config)`、`register(meta)`、`unregister(service_name)`、`on_status_change(callback)`、`close().await`。连接配置支持认证、TLS 和操作超时。注册成功时返回 `Created(handle)` 或 `Existing`。仅新建实例产生清理句柄，句柄绑定服务名和实例 ID。通过句柄注销时，在同一服务的串行操作中核对当前实例 ID，匹配后才撤销该实例的当前 lease。

- [x] 在 `registration` 测试中覆盖并发重复注册、创建 lease 后 Put 或 KeepAlive 失败、恢复期间 close、回调内注销。断言同名服务只有一个 key，失败或关闭后停止重建并撤销已取得的 lease。
- [x] 单个 registry 持有一个 etcd 客户端，按服务保存实例 ID、不可变身份、当前元数据、lease 和取消句柄。注册与注销按服务串行。首次 Put 的 revision 交给自身 key 的监听任务，回调在锁外执行；注销等待 lease 和 watch 任务，回调可重入。
- [x] 从 R+1 监听，遇压缩先线性 Get，再续订。用可控屏障在 Put 和 watch 之间带原 lease 写入 down。分别回放历史、触发压缩，收到状态回调后撤销 lease，断言恢复的 key、注册时间与状态。压缩只在测试进程启动的独立 etcd 上执行。
- [x] 运行 `cargo test --test registration`，再用 `interop/run.sh registry` 在真实 etcd 中观察注销后 key 消失和 close 幂等。

## 3. 发现实例并生成选址快照

文件：`src/discovery.rs`、`src/balancer.rs`、`tests/discovery.rs`。发现订阅通过 Tokio watch 发布最新实例集合；`LbPolicy` 表示三种策略，默认 RoundRobin。

- [x] 测试初始快照、同 revision 的多条更新、空集合、定时全量同步之后的积压事件、watch 意外中断与永久错误。断言只发布 up 实例，更新权重后实例身份不变。
- [x] 按服务前缀 Get、从响应 revision+1 Watch，并提供主动刷新、默认两小时重同步及显式 close。错误记录包含服务和操作，取消同时终止重试计时器。
- [x] 实现 picker，只读取快照中的可用连接。pick_first 保持当前健康选择；轮询使用原子游标；加权策略在小权重周期使用平滑选择表，在大周期用有界空间的加权采样。覆盖默认权重 100、5:1 分布、极大权重、全空与并发读取。运行 `cargo test --test discovery`。

## 4. 将发现结果接入 tonic 客户端

文件：`src/transport.rs`、`src/discovery.rs`、`interop/rust/src/main.rs`、`tests/failover.rs`。交付可 clone 的 `DiscoveredService`，实现 Tower 的 HTTP 请求 Service，生成客户端可直接调用 `EchoClient::new(service)`。

- [x] 先用两个真实监听端验证连接通知。通过 tonic Endpoint 的自定义 connector 观察底层 I/O 终止，用已完成连接建立的 channel 发布可用状态。为地址和每次连接分配独立代号，连接结束事件只影响对应代号。测试覆盖空闲时断线、重连、替换地址后的迟到通知和权重更新复用连接。
- [x] 接入客户端 TLS、keepalive、背压和取消。传输层保留 headers、HTTP body 与 trailers。用本地测试 CA 验证证书和服务名校验。
- [x] `DiscoveredService::poll_ready` 只报告接收容量，空路由表也允许请求进入 `call`。`call` 选不到节点时，以 `Ok(Status::unavailable(reason).into_http())` 返回带 gRPC 状态的响应，有连接故障时保留其原因。通过生成的 `EchoClient` 关闭重试，分别在初始零节点和最后一个节点断开后发起调用，在有界时间内断言 `err.code() == Code::Unavailable`。另让健康节点的 handler 返回同码，断言它仍能接收下一次调用。
- [x] 运行 `cargo test --test failover`。三种策略各跑一次，关闭重试并保留 etcd 的 up 记录，关闭被选端口，等观察到摘除再发请求。恢复端口后分别验证轮询重新分流及 pick_first 可切回。

## 5. 在强类型 unary 调用处实施容错

文件：`src/unary.rs`、`src/breaker.rs`、`tests/unary.rs`。入口 `UnaryPolicy::call(request, deadline, invoke).await` 接收可复制的消息和 metadata，invoke 持有生成客户端的 clone，接收本次请求并返回拥有所有权的 future。

- [x] 使用可控 Tokio 时钟测试首次 Unavailable、第二次成功，两次消息与 metadata 相同，第二次剩余预算更小。测试首次非重试码、退避取消、在途超时和最大尝试数为零。默认最多三次，100ms 起步、倍数 2、最大 1s，重试码按规格。
- [x] 熔断覆盖整个调用。测试五次连续失败打开、十秒后允许一个探测、三次成功关闭，以及上一代请求的迟到结果。使用 RAII 释放被取消的探测名额，支持自定义失败分类。默认重试和熔断均由调用方启用。
- [x] 运行 `cargo test --test unary`。在业务夹具记录实际请求数，验证流方法遇到相同错误时只调用一次。

## 6. 组装服务器与中间件

文件：`src/server.rs`、`src/middleware.rs`、`src/limiter.rs`、`src/metrics.rs`、`tests/server.rs`。用 tonic RoutesBuilder 接收生成的服务。服务器仅保存任务 2 返回的 `Created(handle)`，启动回滚与正常停机都用这些句柄注销。共享 registry 的所有者负责整体 close。

- [x] 回滚测试先注册 A 并记录 key 和 lease，再启动服务器复用 A、新建 B、注入 C 注册失败。断言 B 的 key 和 lease 已清除，A 的 key 和 lease 仍与原值相同，独立发现客户端仍能调用 A。
- [x] 通过 method descriptor 建立 unary 路径索引，供可选令牌桶限流使用；启用限流时校验受管服务的方法描述齐全。用带初始突发容量、可取消等待的测试固定速率下限和配额耗尽行为。流式方法保持按需拉取。
- [x] 用 Tower Layer 实现恢复、日志与可注入 meter 的指标。先从初始响应头读取 `grpc-status`；若已有终态，立即记录。否则把记录权移交给响应体，在最终 trailers 处记录。已开始的流在取得终态前因客户端取消而 drop 时记录 `CANCELLED`。每次调用只消费一次记录权，计数与耗时同步写入。
- [x] 用测试 meter 断言指标名称、单位和标签。分别触发 unary 立即返回 `INVALID_ARGUMENT`、流发出消息后以 `INTERNAL` 结束、客户端收到首条消息后取消仍在等待的流。每例检查对应状态计数增加 1、耗时样本增加 1。另覆盖成功完成、handler panic 和流轮询 panic，断言 panic 转为标准 `INTERNAL`。
- [x] 安装 health Check，对任意服务名返回 SERVING；按配置提供 descriptor 反射、TLS 和 keepalive。停止时先撤销实例再排空在途调用，即使注销失败仍释放监听器。运行 `cargo test --test server`，从标准客户端请求健康检查、反射和限流，并验证停机时已接收的请求完成。

## 7. 在真实进程上验收

文件：`interop/run.sh`、`interop/rust/src/main.rs`、`interop/go/main.go`、`README.md`。两个夹具分别走框架的服务端和发现客户端入口。所有修改注册记录的用例限定在唯一 namespace。

- [x] `interop/run.sh all` 启动独立 etcd、Go 和 Rust 进程。双向断言四类 RPC 的消息数量、顺序、payload、metadata、deadline、取消和最终错误。按规格的六行错误码表逐项核对客户端观察值。
- [x] 两端通过服务名发现对方，验证 down/up 和注销。检查测试成功及失败分支均会终止子进程，删除临时目录，只清理本次测试的资源。
- [x] 权重用例分别运行 Go 客户端调用两个 Rust 实例、Rust 客户端调用两个 Go 实例。每组服务同名，A、B 使用不同地址和实例 ID。客户端显式开启 `weighted_round_robin` 并关闭重试，整个用例复用同一客户端。用一个 etcd 事务更新两条记录，各自保留原 key 和 lease。先设 A:B 为 5:1，再交换为 1:5。
- [x] 每次更新后，在有界时间内通过预热调用等待新分布生效，再独立采样连续 60 次成功 Echo，按响应中的实例 ID 计数。小权重平滑轮询的每个完整周期有 6 次调用，两阶段分别断言 A/B 为 50/10 和 10/50。预热超时、RPC 失败或出现未知 ID 均判失败，并输出该阶段的分布。
- [x] README 给出同一 proto 的生成命令、两端启动顺序、标准状态码边界、TLS 和显式关闭示例。记录实测版本与环境要求。
- [x] 最终执行 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 和 `interop/run.sh all`。分别报告库测试和跨进程互通结果。
